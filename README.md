# Polyglot-Data-Platform
1. Executive Summary & Architecture OverviewPolyglotAI is an enterprise-grade, metadata-driven data platform built on Azure. It is designed to ingest, process, and govern multi-format enterprise data streams (tabular structured and nested semi-structured data) using a scalable Medallion Architecture 
(Raw -> Bronze -> Silver -> Gold) backed by open-source Delta Lake storage.

2. Core Tech Stack & JustificationAzure SQL Database (Control Plane): Serves as the lightweight metadata repository. Stores pipeline configurations, active source mappings, and incremental watermark values to maintain decoupling.Azure Data Factory (Orchestration Engine): Drives metadata-driven, loop-based orchestration (Lookup + ForEach + Copy Activity), eliminating hardcoded pipeline logic and scaling effortlessly as new sources are added.Azure Data Lake Storage Gen2 (Storage Layer): Provides secure, hierarchical namespace (HNS) storage separating data into logical containers (raw, bronze, silver, gold).Azure Databricks & Apache Spark (Processing Engine): Executes distributed compute operations, parsing raw multi-format streams, enforcing schema validation, and writing ACID-compliant Delta Lake tables.Azure Key Vault (Security & Governance): Manages enterprise secrets securely via Databricks Secret Scopes using OAuth client credentials flow (fs.azure.account.auth.type = OAuth).

3. End-to-End Data Flow & Ingestion MechanicsMetadata Lookup: ADF queries the Azure SQL control table to fetch active datasets (e.g., employees CSV, api_responses JSON) along with their target container and directory paths.Dynamic Ingestion: A ForEach loop dynamically passes parameters (.TargetContainer, .TargetDirectory) to a generic ADF Copy Activity, landing untouched files securely into ADLS Gen2 raw.Cluster Boot & Security Initialization: Azure Data Factory triggers a Databricks job run. Databricks securely authenticates against ADLS Gen2 using OAuth credentials fetched dynamically from Azure Key Vault.Medallion Transformations:
Raw -> Bronze: Ingests raw files, adds system metadata (_metadata.file_path, _ingestion_time), and lands them into an append-only Bronze Delta table.
Bronze -> Silver: Cleanses data, handles type casting, parses nested fields, and applies dynamic regex filtering.

Silver -> Gold: Aggregates and merges business-ready datasets (e.g., joining employee metrics with API metrics) into unified analytics-ready Delta tables with complete audit trails.

Q1: Why did I choose a metadata-driven architecture over hardcoding pipelines in Azure Data Factory?Architectural Answer: "Hardcoding pipelines creates a maintenance bottleneck. If an enterprise has 500 sources, building 500 copy activities leads to technical debt. By using Azure SQL as a control table combined with ADF Lookup and ForEach activities, our orchestration layer becomes dynamic. To onboard a new data source, we simply insert a row into our SQL control table, and the pipeline automatically scales without changing a single line of ADF canvas design."
Q2: How do I handle security and credential management between Databricks and ADLS Gen2?Architectural Answer: "We strictly avoid hardcoding storage keys or service principal secrets in notebooks. Instead, we use Azure Key Vault backed by Databricks Secret Scopes. Databricks authenticates to ADLS Gen2 using OAuth 2.0 Client Credentials Provider (ClientCredsTokenProvider), passing scoped client IDs and client secrets securely at runtime."
Q3: What are the primary benefits of using Delta Lake over standard Parquet files in your Silver and Gold layers?Architectural Answer: "Parquet files are immutable and great for columnar storage, but they lack transactional guarantees. Delta Lake sits on top of Parquet and provides ACID transactions, time travel (data versioning), schema enforcement, and optimized file compaction (OPTIMIZE/VACUUM), which is essential for production data quality and audit compliance."
